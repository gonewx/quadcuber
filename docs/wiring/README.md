# 电路总览

本页统一说明当前方案、可选方案和验证进度。逐线接法以本仓库生成的 HTML/SVG 为准；外部发布页面需在修改后同步更新。

## 当前基准

- 主控：Pico，调试时由 USB 供电；5V 电源轨不接 Pico 供电脚。
- 马达：EV3 大马达，DRV8833 A 路，名义 9V 输入。历史测速时 VM 实测约 7.9V，详见[实测记录](../single_arm-results.md)。
- 编码器：5V 供电，A/B 各经 10kΩ 串联＋20kΩ 对地分压，固件 `ENC_PULLUP=False`。
- R 臂：GP2/GP3 驱动、GP4/GP5 编码器、GP8 舵机；STBY 固定接 Pico 3V3。
- 当前装配：**面包板承载低电流信号，动力独立走线**。v3 固件齿轮比为 2.5；空载记录使用 1.0，测试参数不能直接混用。

## 当前装机顺序

**一次接齐马达、编码器和舵机，再分项发命令测试。** 舵机后接是之前排查驱动故障时的可选隔离方法，不是 v3 装机的必经步骤。

1. 断开 USB 和 9V，按下文完整接线连接全部设备。
2. Pico 先接 USB，启动测试程序并输入 `off`，再接通 9V。
3. 按[单臂测试第 5 节](../single_arm.md#5-测试步骤)依次确认马达方向、齿轮比、标定舵机，再做旋转和联合测试。舵机标定前不运行旧的开合预设；全程无需为了分项测试反复插拔。

## 两种装配方案的区别

两者使用相同的 GPIO 和分压阻值，但外部供电走线不同。选定一种方案后按该页完整接线，不能混用线号和孔位。

| 部分 | 当前直连 | 可选洞洞板 |
| --- | --- | --- |
| 马达动力 | DC-005、驱动、EV3 直接线连 | J1 输入，经 U1 到 J4 |
| 降压输入地 | P04 从 DC-005 负极直接接降压 IN− | W04 直接回 J1.2 |
| 舵机供电 | OUT+/OUT− 独立引线 | J5，由 W05/W07 供电和回流 |
| 面包板供电 | P09/P10 | J6 |
| 控制信号 | Pico 直接接驱动/舵机 | 经过 J7 |

**完整接线要点：**P04 从 DC-005 负极直达降压 IN−；舵机红/棕线分别直连降压 OUT+/OUT−，黄线接 GP8。断开 USB 和 9V 后按完整图接线，见[直连页](direct-breadboard.html#complete-wiring)。

## 维护与生成

从仓库根目录运行（仅使用 Python 标准库）：

```bash
python docs/wiring/build.py
python docs/wiring/build.py --check
python -m unittest -v
```

`--check` 在临时目录重建并逐字节比较，不改工作区；缺失或过期的产物会返回非零退出码，CI 也执行此检查。

| 源文件 | 职责 / 产物 |
| --- | --- |
| `spec.py` | 共享四臂引脚表、驱动脚序，核对固件与 GPIO/PWM/PIO 分配 |
| `direct_wiring.py` | 当前直连孔位、导线、电阻；生成 `direct-breadboard.html`、`.svg`、`-netlist.json` |
| `perfboard_layout.py` | 可选洞洞板孔位与裸板网络；生成五张 `perfboard-*.svg`、章节 HTML、`../perfboard.md` |
| `build.py` | 统一入口；生成总览、洞洞板页面，并更新 `../single_arm.md` 中标记的引脚表 |

生成文件应随源文件一起更新；`single_arm.md` 只有 `wiring:pin-table` 标记之间的表格自动生成，其余章节手动维护。`direct-breadboard.png` 是完整 SVG 的浏览器导出图，修改图纸后需同步导出；`--check` 比较 HTML、SVG、JSON 和 Markdown，不比较 PNG。

图纸包含固定孔位和绘图坐标。修改固件引脚后，检查会要求同步复核图纸，**不会自动重布线**。网络检查覆盖连通、网络隔离、电阻未被短接、孔位占用及洞洞板镜像；不覆盖真实接触电阻、温升、电源瞬态和实物接线。
