# 历史 v4 机械说明与 R／L 独立调试

**本文机械尺寸与装配步骤针对历史 v4 单臂模块**：反向连杆往后拉夹紧，转盘内 39793 导向，竖墙与舵机侧加固。历史模型见[固定版本源码](https://github.com/gonewx/quadcuber/blob/e9d56112fa59c3301faa3b19b167e14e95b1e212/tools/lego/v4/model.py)，当时的搭建与修改见 [历史 v4 设计说明](https://github.com/gonewx/quadcuber/blob/e9d56112fa59c3301faa3b19b167e14e95b1e212/docs/lego/v4/README.md)。名义 CAD 检查不能代替实物验收；下一步是实物标定和分级测试，尚未完成 v4 夹紧力、保持力、旋转及四臂联合验证。

**最终整机搭建入口：**[501 步装配说明](../generated/site/integrated-assembly.html)。下文历史机械尺寸不能直接作为最终整机装配依据；固件的 v4/R 标定身份保持不变，仍须按实际机构核验。

**先做断电手动检查**：历史 v4 模块按 [v4 实物验收](https://github.com/gonewx/quadcuber/blob/e9d56112fa59c3301faa3b19b167e14e95b1e212/docs/lego/v4/README.md#实物验收)确认全行程避让、挡轴留隙、活动轴保持和底座刚度。保留开端挡轴作为异常保护，不能让舵机持续顶住挡轴，也不能把折叠死点当作必须到达的夹紧位置。

目标：用 **1 个 v4 机械手**（上下轮胎压头＋转盘）回答三个问题：

1. 转 90° 要多久？（直接决定总时间）
2. 到位精度多少？（误差大了，下一次拧面会卡住）
3. 夹持是否可靠？（拧面时魔方不打滑、不掉，夹指不被顶开）

- **怎么测**：本文第 4、5 节。第 5 节开头先约定了方向、零位、夹紧/松开的含义，测试前请先看。

## 2. 引脚分配

单臂用 R 臂的引脚。接线唯一数据源为 `wiring/spec.py`，下面引脚表由它生成，不随机械版本手改。整机 4 个臂的分配已经一起排好，**PWM slice 不冲突**（RP2040 上 GPIO 号相差 16 的两个引脚共用同一路 PWM，不能随便挑）：

<!-- wiring:pin-table:start -->
| 用途 | R 臂 | L 臂 | F 臂 | B 臂 |
| --- | --- | --- | --- | --- |
| 马达 IN1 / IN2 | GP2 / GP3 | GP6 / GP7 | GP10 / GP11 | GP14 / GP15 |
| 编码器 A / B | GP4 / GP5 | GP12 / GP13 | GP16 / GP17 | GP18 / GP19 |
| 舵机 | GP8 | GP9 | GP20 | GP21 |
| PIO 状态机 | 0, 1 | 2, 3 | 4, 5 | 6, 7 |
<!-- wiring:pin-table:end -->

- UART 连 Zero W：GP0（TX）→ Zero 的 GPIO15（RX），GP1（RX）← Zero 的 GPIO14（TX）。
- 剩余引脚：GP22、GP26、GP27、GP28，可以留给限位开关或 DRV8833 的 nFAULT。
- 编码器用 4 倍频，每个编码器占 2 个 PIO 状态机，4 个臂正好用完 8 个。如果以后 PIO 不够用，可以改成 2 倍频（每个编码器 1 个状态机，分辨率减半）。

## 3. 接线

### EV3 线（6 芯）

| EV3 脚 | 常见线色 | 功能 | 接到 |
| --- | --- | --- | --- |
| 1 | 白 | 马达 M1 | DRV8833 AOUT1 |
| 2 | 黑 | 马达 M2 | DRV8833 AOUT2 |
| 3 | 红 | GND | 公共地 |
| 4 | 绿 | 编码器电源 | 5V（降压模块） |
| 5 | 黄 | 编码器 A 相 | 10kΩ → GP4（GP4 再经 20kΩ 接地） |
| 6 | 蓝 | 编码器 B 相 | 10kΩ → GP5（GP5 再经 20kΩ 接地） |

> ⚠️ 线色是常见的配色，**不同的线可能不一样，以万用表通断为准**。马达的两根线（1、2 脚）之间电阻大约几欧到十几欧，可以借此确认。

### 编码器分压（重要）

**RP2040 的引脚不耐 5V**，编码器信号直接接 Pico 会损坏芯片。

LEGO 官方电路：EV3 马达里两路编码器都是施密特缓冲器，**推挽输出 0V/5V**，各经一个串联电阻到插头：6 脚（蓝）3.3kΩ，5 脚（黄）的电阻兼作马达型号识别（大马达 3.3kΩ、中马达 6.8kΩ）。所以每路只要两个电阻分压：

```
EV3 黄 ──[10kΩ]──●── GP4        EV3 蓝 ──[10kΩ]──●── GP5
                 │                                 │
              [20kΩ]                            [20kΩ]
                 │                                 │
                GND                               GND
```

- ● 是面包板上的同一排：10kΩ 的一脚、到 GP 引脚的跳线、20kΩ 的一脚插在一起；20kΩ 的另一脚接地轨。
- 算上马达内部电阻，高电平：大马达约 5 × 20 / 33.3 ≈ 3.0V（中马达黄线约 2.7V）；低电平约 0V。Pico 要求高 ≥ 2.0V、低 ≤ 0.8V，裕量充足。
- 替代阻值（结果都在 2.7~3.0V）：20kΩ 换成 22kΩ 或两个 10kΩ 串联；或者 4.7kΩ 串联 + 10kΩ 下拉。
- 固件里 `ENC_PULLUP = False`，不能开 Pico 内部上拉（会抬高分压点）。
- **接 Pico 之前先验收**：编码器通电（绿 5V、红地），分压点先不接 Pico，用万用表量分压点对地的电压；手转输出轴，每次转一点停下来读，应在约 0V 和约 3V 之间变化，**任何时候都不能超过 3.3V**。两路都正常再接 GP4/GP5。

不要用 BSS138 或 TXS0108E 电平转换模块：马达内部的串联电阻和 BSS138 模块的上拉会分压，低电平只能到约 1.65V（实测 1.60~1.64V）；TXS0108E 要求信号源内阻很低，同样不适用。

### 马达驱动

| DRV8833 | 接到 |
| --- | --- |
| VM（有的标 VCC） | 9V；本版不另装电容，保留模块自带电容 |
| GND | 公共地 |
| AIN1 / AIN2 | GP2 / GP3 |
| AOUT1 / AOUT2 | EV3 线 1、2 脚 |
| nSLEEP（有的标 EEP / STBY） | 本项目已确认的模块 STBY 接 **Pico 3V3**；其他模块需先核对丝印和电路 |

> ⚠️ **DRV8833 的马达电压最高 10.8V，不能接 12V。** PWP/RTY 封装每桥为 1.5A RMS、2A 峰值，PW 封装为 0.5A RMS、2A 峰值；实际板卡受散热和限流设置影响。大马达 9V 堵转实测约 1.8A，不能当持续工作点；软件保护不能代替硬件限流。当前驱动板的电流裕量尚未确认。

### 舵机

- 信号线 → GP8；电源 → **单独的 5V 降压模块**（不要从 Pico 取电，舵机启动电流会让 Pico 复位）；地线 → 公共地。

### 供电和地

- 所有模块**共地**：Pico GND、DRV8833 GND、5V 降压模块 GND、9V 电源负极、EV3 线 3 脚。
- 调试时 Pico 用 USB 供电即可。以后脱离电脑时，从 5V 经**肖特基二极管**接 VSYS（防止和 USB 供电互相倒灌）。

### v4 完整接线：一次接齐，动作分项测试

大马达空载测试已经通过。当前装机可以在断电状态下**一次接齐马达、编码器和舵机**，接好后按第 5 节分项发命令，不需要测完马达再插舵机。

1. 断开 USB 和 9V。降压输出应已空载调好至 5.0V。
2. **P04 接 DC-005 负极 → 降压 IN−**，作为降压模块的独立回流。
3. 舵机红线接降压 OUT+、棕线接 OUT−，均为独立动力引线；黄线接面包板 j13（GP8）。核对实际线序，电源不从面包板或 Pico 取。
4. 马达、编码器和其余控制线按[当前接线：原 R／新 R+L（条件式）](../generated/wiring/direct-breadboard.html#complete-wiring)连接。图中已包含舵机及全部动力、信号接线。

**分项测试是命令顺序，不是接线顺序：**马达方向 → 齿轮比 → 舵机开合标定 → 旋转及联合测试。仓库 R 分组已填写 `SERVO_OPEN_US = 1700`、`SERVO_CLOSE_US = 1450`，但仍为 `SERVO_CALIBRATED = False`；仅填写脉宽不代表完成标定；未标定时 `open`、`close`、`grip`、`cycle` 会拒绝执行且不启动马达。手动标定会话期间也拒绝这四条命令，不能绕过第 3 步。

未标定时普通马达动力命令也拒绝执行。第 0～2 步需显式使用 `motor_test unloaded`；它只是空载测试授权，不把舵机标记为已标定，也不允许带魔方试运行。实际安全工作区间 `SERVO_MIN_US` / `SERVO_MAX_US` 也默认为 `None`，实测、身份绑定与写回见第 3 步。

只有重新排查复位、供电跌落或驱动异常时，才可在断电后暂时拔下舵机，单独检查马达和编码器；P04 保持直接回电源负极即可。

## 4. 升级为 R／L 独立调试（保留设备 R 配置）

常规 `arm>` 模式一次只调试一臂；第4.5节的显式 `static supported` 仅提供外部支承承重下的双舵机静态定位，不执行马达协同。在动作结束返回提示符后选臂；控制循环执行期间会阻塞，排队的选臂命令不能代替 Ctrl+C 或切断动力的停止操作。默认 R；在 `arm>` 输入 `arm L` 或 `arm R` 选臂，输入 `arm` 查看当前臂、引脚及配置文件。`ARM_ID` 本身仍不改 GPIO；选臂命令会校验固定接线并加载该臂完整配置。

| 配置 | R（保留设备现值） | L（独立新配置） |
| --- | --- | --- |
| 同一 `firmware/pico/config.py` 内的分组 | `ARMS["R"]` | `ARMS["L"]` |
| 马达 IN1 / IN2 | GP2 / GP3 | GP6 / GP7 |
| 编码器 A / B | GP4 / GP5 | GP12 / GP13 |
| 舵机 | GP8 | GP9 |
| PIO 状态机 | 0 / 1 | 2 / 3 |

每次选臂（包括重复选择当前臂）先停止输出、释放旧 PWM、停用旧 PIO，再初始化新臂；临时 `servo_cal` / `motor_test` 授权、编码器零位、轨迹与在线 `set` 参数重置。配置文件中的记录不被选臂改写。**每次 Ctrl+D、断开 USB 或重启程序后默认重新选择 R，不记住上次的 L。动力保持关闭，先重新选臂（L 用 `arm L`，R 用 `arm R`），再输入 `arm` 核对臂名、引脚与配置，之后才建立会话或通电。**无效选择或初始化失败会保持停止，需重新 `arm R` / `arm L`；不自动回退并恢复运动。未选中臂的两个驱动输入和舵机信号明确保持低电平。退出程序也释放资源并保持这些输出为低；**上电到程序启动之间、硬件故障或复位期间不由这个程序保证，升级和重启必须关闭动力。**

### 已运行原 R 固件的升级

R 空载旋转已通过，无需为了升级重做。先保存 R 测量记录；候选松开 1700、接触 1500、夹紧 1450 只属于 R，不能当作 L 端点或 L 已标定状态。不要用仓库的 `config.py` 覆盖设备文件。

1. 关闭动力电源（包括舵机 5V），只留 USB；在原 `arm>` 输入 `off`、`quit`。退出其他占用串口的终端。
2. 在**仓库根目录**的电脑终端先备份设备配置；下面备份名若已存在，请换一个新名称，勿覆盖旧备份：

   ```bash
   mpremote fs cp :config.py ../quadcuber-R-config-before-L.py
   ```

   确认备份文件存在且包含当前 R 参数。该文件是回退与保留校准值的依据；无需重新推测或重测已有 R 数值。
3. 在电脑上从**刚下载的设备备份**生成新配置，再独立校验。以下工具不连接设备，不执行备份中的 Python，也不覆盖输入或已有输出：

   ```bash
   python tools/migrate_arm_config.py migrate ../quadcuber-R-config-before-L.py ../quadcuber-config-RL.py
   python tools/migrate_arm_config.py verify ../quadcuber-R-config-before-L.py ../quadcuber-config-RL.py
   ```

   R 的全部字面值（包括用户额外字段、控制增益、方向和实测标定）原样放入 `ARMS["R"]`。L 使用独立未标定模板，绝不从设备 R 复制标定。备份含计算、导入、重复赋值、缺失必需字段或接线不匹配时工具停止，不生成可上传文件、不用默认值补齐。此时保留旧配置即可继续 R；先核对备份，人工把计算结果明确写成字面值后另存再试，不要运行来源不明的配置。已经采用 ARMS 的配置拒绝重复迁移，以免重置已有 L 记录。

   唯一人工维护入口的结构如下（省略号仅示意，勿直接上传）：

   ```python
   ARMS = {
       "R": {"ARM_ID": "R", "SERVO_OPEN_US": 1700, ...},
       "L": {"ARM_ID": "L", "SERVO_OPEN_US": None, ...},
   }
   ```

   示例 R 值不是设备替代值；上传文件必须来自实际备份的迁移结果。后续每次改参数只编辑对应分组，例如 `ARMS["L"]` 内的 `GAINS` 和端点，两臂不得共用同一个字典。
4. 动力继续关闭，先更新程序文件；此时旧平铺 `config.py` 仍支持原 R。`arm L` 会停止输出并提示先迁移，不会借用 R 配置。

   ```bash
   mpremote fs cp firmware/pico/arm_profiles.py firmware/pico/control.py firmware/pico/encoder.py firmware/pico/motor.py firmware/pico/static_pair.py firmware/pico/arm_test.py :
   mpremote fs cp ../quadcuber-config-RL.py :config.py
   mpremote fs cp :config.py ../quadcuber-config-RL-readback.py
   python tools/migrate_arm_config.py verify ../quadcuber-R-config-before-L.py ../quadcuber-config-RL-readback.py
   ```

   下载回读也请使用尚不存在的本地文件名。任一传输或校验失败，不接通动力、不运行测试；从电脑上的原始备份恢复 `mpremote fs cp ../quadcuber-R-config-before-L.py :config.py`，重新下载核对与备份逐字节一致，再 Ctrl+D 重启。新程序兼容原平铺 R，无需把默认配置写回设备。如果升级前还使用了自定义程序版本，也应先另行备份所有程序文件供整套恢复。上传中断可能留下不完整文件，必须恢复并核对后再启动。
5. 校验通过后打开 REPL，动力仍保持关闭：

   ```bash
   mpremote repl --capture arm-L.log
   ```

   在 `>>>` 按 **Ctrl+D**，再运行 `import arm_test; arm_test.main()`。默认 R；在 `arm>` 输入 `arm L`、`arm`、`help`，应显示 L、`config.py ARMS[L]`、GP6/7、GP12/13、GP9、PIO(2, 3)。这些命令不发定位脉冲；`help`、`arm`（无参数）、`show`、`enc`、`trace` 是查询命令。`set` 不改选臂或 GPIO，不持久化到文件。

配置必须仍符合固定 R/L 接线。`arm_profiles.py` 仅是读取分组的程序，不是第二个人工配置文件；不再使用 `config_l.py`。后续升级先备份当前**整个** `config.py`，勿重新迁移或覆盖已标定的 L。新设备才可用仓库模板初装。只重复 `import` 不会重新读取缓存配置，改参数后须关闭动力、上传同一个 `config.py` 并 Ctrl+D 重启。

### L 的首次标定与切回 R

先关闭动力和 USB，脱开 L 舵机连杆，确认曲柄自由行程；不放魔方。再按下文 B 的条件启动、选 `arm L` 并 `off`，才给已检查的硬件供电。L 的方向、机械传动比和控制初值尚未实测，R 的空载结果不等于 L 已验收。

`config.py` 的 `ARMS["L"]` 默认 `SERVO_CALIBRATED=False`、`SERVO_TIMING_CONFIRMED=False`；开合端点、安全区间、标定身份和等待时间均为 `None`。首次命令形式为：

```text
servo_cal <min_us> <max_us> <start_us> detached
servo <start_us>
```

尖括号是待人工确认后替换的整数，不是可直接粘贴的命令。第一行仅授权、不运动，第二行才发首脉冲，且必须等于声明的 start。保留原有规则：首次脱杆；装接后只有核实轴位才能使用 `aligned`；500～2500 只是电气包络；后续脉宽可在声明区间内作绝对跳转，程序不限制相邻差值，不代表机构可安全大步运动。未知区间继续小步、停稳观察，不自动扫角。

L 实测完毕后只在 `config.py` 的 `ARMS["L"]` 记录 L 的端点、安全区间、`SERVO_CALIBRATION_ARM="L"` 与匹配的机械身份，再按下文分阶段确认等待时长和时序；不得复制 R 的确认标志。`open` / `close` / `grip` / `cycle` 等继续受原门禁限制。原 R 的标定记录留在同一文件的 `ARMS["R"]`，R/L 的 `GAINS`、方向、传动比和时序各自独立。

结束时 `servo off`，关闭动力，再 `arm R`；切回不会定位，也不会恢复旧临时授权，重新建立必要的零位和本次测试会话即可。R 已通过的空载旋转无需重做。两臂分开保存日志，不将 L 数据直接覆盖 R 的测试记录。本节新增的是选臂和配置隔离；下文机械尺寸、连杆朝向与 CAD 角度仍只描述历史 v4，实际装配须单独核验。

## 4.5 L/R重复定位、分别校零与水平装料准备

本节针对当前56 mm标准模型、仅L/R已装的阶段。先解决重复定位和实际夹头零位，再决定是否修改夹指；不采用独立底座加固提案，也不改变R设备实测参数。**常规选臂仍停止旧输出；新增静态模式只允许托盘或独立支承全程承重时分别定位两路舵机，不支持同步翻转。** 下列准备步骤不代表水平承重已经验收。

### A. 现在先做：无魔方、动力关闭，查询R状态

取下魔方，关闭EV3马达及舵机动力，保留USB；若托盘在上位，以独立支承控制回落，不让它自行跌落。在已经运行本仓库R/L版程序的 `arm>` 提示符下输入：

```text
off
arm R
arm
show
enc
```

这些命令不发定位脉冲。`arm R` 会停止两臂输出并重建R会话；所以紧接着看到编码器接近0，不代表机械头实际竖直。暂不输入 `zero`，不批量粘贴任何运动命令。常规 `arm>` 没有 `home`、`jog`、`status` 或双臂 `load` 命令；`status` 仅在下述 `static>` 内使用。

若 `arm` 命令不存在，先按第4节保留设备配置升级程序；不要用仓库 `config.py` 覆盖设备文件。R的接触1500、夹紧1450、通过1700 µs仅作为已有R记录，不代表L端点，也不单独证明安全区间或时序已确认。

### B. 每臂分别建立机械零位，不强行回驱EV3齿轮箱

竖直零位是上下两个轮心的连线竖直；在顶／底面中间列的前后方向都居中。L/R共同回转轴应穿过魔方侧面中心；托盘上位面Y28对应56 mm魔方中心Y0。不能用“编码器显示0”代替这个机械基准。

EV3内部减速器和24:60外部齿轮会抵抗回驱。`off` 使马达滑行，但没有机械脱开传动；停舵机PWM也不等于断开5V。不要抓轮胎或夹指强扳齿轮箱，不要强扳带电舵机；手动调整连杆必须先切断动力。

R已有空载方向和传动比实测记录，不必重跑其整套测试。移走魔方、托盘降下、机构自由行程已核实、手和工具退出后，可用现有空载模式进行**有动力的小角度定位**，不以手强扳：

```text
motor_test unloaded
enc
```

此时仍未运动。根据实际偏角使用 `goto <绝对角度>`；目标是当前编码器坐标中的机械头角度，不是增量。例如当前读12°且距竖直还需负向3°时，目标是 `goto 9`；这是计算示例，不是本机待执行目标。先利用本臂已验证的方向和控制参数；未知大行程不要直接 `goto 90`。到位后以轮心连线复核，出现提示符并不证明机械零位准确。

确认停稳并对准后输入：

```text
off
zero
enc
```

`zero` 只把当前位置记作0，不寻零、不移动、不写配置文件。`off` 已撤销空载授权，下一次运动需重新声明。记录R实际零位标记，再关闭动力、选 `arm L`，重复查询和对准。**L方向、传动比未核实前，不照搬R的 `goto` 行为**；先按第1、2步完成L必要的空载方向和比例验证。每次选臂或重启都重新建立该臂编码器原点；不是把R零位保存下来后程序就能同时记住L/R物理状态。

### C. 先用基准区别位置偏移，再分别标定接触

断电、独立托稳魔方，在顶／底面用可移除细线标出中间列中心线，检查轮心投影，不需要反复拍照。原托盘只有＋X、＋Z两个单向靠边，轻靠两面才形成装料基准；没有反向预紧，未贴紧时仍可向−X／−Z串动。

- 上下压点同向偏：优先检查魔方平移、偏航及是否真正靠边。
- 上下压点反向偏：优先检查夹头零角或结构歪斜。轮胎中间截面的几何估计为上下各偏 `±28tanθ`；1°约0.49 mm、5°约2.45 mm，不是实测压斑中心。
- 竖直时，R目标为UR／DR棱块的顶／底面，L为UL／DL；不是压住侧面中心块。
- 名义压点距L/R外缘约3.91 mm，靠外缘本身可以正常；实际接触斑不能跨到角块或邻层缝。轮胎完整外轮廓不能当作接触斑。

**不要在原上位托盘上强行竖直闭合L/R。** 当前名义几何的下轮胎与中央承托梁、H座和固定销存在三角面相交；只取掉中间梁也没有解决全部空间问题。静态参考可以观察，但不能把托盘顶偏造成的现象用增加夹紧量补偿。

接触标定仍按第3步的会话规则，每次仅一臂，魔方重量由独立支承承担，不能依赖未选中的另一臂。进入会话的真实命令形式为：

```text
servo_cal <min_us> <max_us> <start_us> detached
servo <start_us>
```

首次L定位必须满足脱杆条件。装接后只有已核实轴位和基准对应关系，才使用 `aligned`。尖括号必须替换为本臂确认的整数，不是可直接粘贴的值；R也不能仅凭1500记录就跳过这些前提。首次脉冲必须等于本次声明的start；之后 `servo <us>` 可以在声明区间内直接指定绝对值，**没有固定20 µs步长限制**。已检查过的自由区间无需机械地重复20 µs小步；未知端点附近仍分段观察，不自动扫角，也不把脉宽跳转理解为受控慢速。

为R、L分别记录：实际竖直基准、刚接触值、可靠夹紧值、通过值、已确认安全区间、接触是否跨缝，以及夹紧前后是否偏移。只写入设备文件中对应 `ARMS["R"]` 或 `ARMS["L"]` 分组，不改另一臂；等待时间和确认标志仍须按第3步分别验证。此次不要求重做已经通过的R空载旋转。

### D. 水平姿态：目前只允许逐臂空载准备

水平指同一夹头的两个轮胎分居魔方的前后（F/B）方向，张合平面由竖直转成水平；不是把整只机械臂横移。零位有效、方向和相应空载行程已经核实时，现有命令 `goto 90` 或 `goto -90` 表示机械头绝对±90°；`rot 1` 是从名义目标再加90°，不能混用。

目前可在无魔方、托盘降下时分别核对R与L的水平几何姿态；每次选臂会重置软件原点，必须重新核实零位，不能选L后直接复用R的角度状态。未选中头的保持状态不由程序保证，因此“分别摆成水平”不等于已经得到可承重的双臂装料状态。

### E. 水平装料接管：候选分段及明确阻断

| 阶段 | 设计关系 | 当前允许边界 |
|---|---|---|
| 1 | 两臂水平、托盘升起，56 mm魔方轻靠原两定位边 | 可以断电核对位置；有魔方时必须有独立可靠支承，不依赖未选中臂 |
| 2 | 支承全程承重，分别定位L/R舵机并观察接触 | 仅允许下述静态模式；**不能据此认定两臂接管重量，水平承重未实测** |
| 3 | 保持两臂夹持，空托盘下降40.8 mm | **阻断：静态定位不证明承重，不得降盘或撤去支承** |
| 4 | 如需竖直姿态，由L/R一起带整颗魔方转90° | **阻断：没有双臂同步命令，也未验证同步及承重** |

代码中的 `arm L` / `arm R` 会先关闭旧臂输出；**不能执行“R close → arm L → L close”冒充双臂接管**。`goto` / `rot` 都只作用于当前一臂；先转R再转L也不是整颗同步翻转。不要用两个独立测试实例争用引脚、PIO和输出，也不要通过保留旧PWM绕过选臂停止规则。

该候选不要求F/B已安装，但魔方会随整颗90°翻转改变朝向，不能继续沿用转前面定义。几何检查只支持：水平闭合及33个开合采样姿态不碰上位支承；下位时L/R和理想56 mm魔方的90°解析扫掠包络不碰支承总成。没有证明夹持力、实时同步、全部自碰撞或交接安全。

### F. 显式双舵机静态定位：支承全程承重

升级时同时复制 `static_pair.py`，按第4节备份和核对设备文件，不覆盖设备 `config.py`。以下模式尚需实物台架验证；首次使用先脱杆、无魔方检查两路信号及停止行为。之后有魔方时，托盘或独立支承必须承担全部重量，始终禁止降盘、撤支承、同步转头或整颗翻转。原托盘上位不能进行竖直闭合，见C节。

在 `arm>` 输入 `static supported` 进入 `static>`。进入会关闭原臂输出、释放马达PWM与编码器PIO；不发舵机定位脉冲，也不保留马达位置控制。两路舵机GP8/GP9共用PWM slice4，统一50 Hz、统一停止；只调整L不会撤掉R信号。本模式不创建马达或编码器控制对象。`status` 分别显示两臂授权、安全范围、指令脉宽、目标和剩余时间；没有舵机位置反馈，显示值不证明实际轴位。

命令形式如下，尖括号必须替换为该臂已核实数据；逐条输入并观察，不批量粘贴：

```text
status
cal R <R最小脉宽> <R最大脉宽> <R首脉宽> detached <时限秒>
start R <R首脉宽>
cal L <L最小脉宽> <L最大脉宽> <L首脉宽> detached <时限秒>
start L <L首脉宽>
status
move R <R目标脉宽> <速率> verified
move L <L目标脉宽> <速率> verified
status
```

`cal` 只授权，不发脉冲；R/L范围、首脉宽及时限分别声明，不继承另一臂。L不能套用R的1500/1450/1700记录。已有配置安全范围即使尚未完成全部标定也不能扩大；标定完成时还要匹配臂和机械身份。此模式不改写配置、标定标志或零位。

首次定位必须脱杆；只有已核实实际轴位、装接基准和自由行程，才可把 `detached` 换成 `aligned`。`start` 每臂仅一次，必须等于声明首脉宽；实际轴位未知仍可能大幅跳转，后续限速不能保护首脉冲。`move` 只接受本臂已核实区间内的目标，必须显式给出10..200微秒/秒速率和 `verified`；每次至少间隔20 ms、最多改变4微秒，停顿后不追赶补跳。速率只是指令脉宽变化率，不能保证实际机械速度、夹紧力或舵机响应。未知区间仍需先单臂标定，不自动扫角。

每臂时限5..120秒，从 `cal` 开始计时；`status` 和运动命令均不续期。再次确认支承后，用 `renew R supported` 或 `renew L supported` 只续对应臂原时限。任一授权到期，两路都停止；目标预计运动时间须留有至少1秒余量，运行迟滞仍可能导致途中超时。输入半行后停顿也继续计时；轮询后每次只读一个原始字节，不等待UTF-8字符补全。仅接受ASCII命令，非ASCII或不支持的控制字节立即共同停止。

`off` / `quit`、Ctrl+C、输入结束或检测到连接错误、非法命令、任一路异常及超时都会停止两路信号并撤销授权；不会发送松开端点。**停信号不会切断5V，不保证夹指卸力或保持；重量始终由支承承担。** 超时为协作式软件检查，解释器、输出阻塞或硬件故障可能延迟停止，不能替代断开动力。部分串口断连无法立即检测，只能等软件时限。结束后回到 `arm>`，须重新 `arm R` / `arm L` 才建立单臂会话，不自动恢复输出。

此阶段完成标准是两臂独立定位、查询、限速及共同停止在实物支承条件下验证通过；仍不放行重量交接、自动降盘或整颗翻转。


## 5. 测试步骤

下文提到的配置字段均编辑在所选臂的 `ARMS["R"]` 或 `ARMS["L"]` 字典内，以 `"字段": 值,` 的语法填写，不在文件顶层新增同名赋值。L 的标定身份必须为 `"L"`。

所有命令都在 `arm>` 提示符下输入，`help` 可以查看全部命令。马达、编码器和舵机可提前全部接好。先看下面的约定，再按第 0~9 步依次测试，**每一步通过了再做下一步**；测试过程中无需反复插拔舵机。

### 开始之前：几个约定

**角度**：马达命令里的角度、速度全部指**机械头（转盘）**，不是马达的。v4 是 24 齿带 60 齿转盘，机械头转 90° 时马达要转 225°，`config.py` 里 `GEAR_RATIO = 2.5` 负责换算。舵机标定命令使用微秒脉宽，不使用这些角度。

**正方向**：**站在机械手后面（舵机那一头），朝魔方方向看，机械头顺时针转为正。**

- `rot 1` = 顺时针 90°，`rot -1` = 逆时针 90°，`rot 2` = 顺时针 180°。
- 这和规划器的约定一致（`quadcuber/machine.py`：“从机械手一侧看顺时针”），以后整机直接用，不要再换。
- 齿轮会把方向反过来：机械头顺时针时马达输出盘是逆时针。**判断方向只看机械头，不看马达**。
- `check` 只能检查“马达和编码器是否一致”，查不出机械头转向对不对，所以第 1 步还要用 `duty` 目测一次。

**零位**：两片夹指一上一下（夹指张合的平面竖直）的位置是0°。启动或选臂建立的编码器原点不代表机械零位。先按第4.5节B核实实际竖直姿态，再在停稳后 `off`、`zero`、`enc`；不要强行回驱EV3齿轮箱。`off` 撤销两种手动会话，继续空载定位需重新检查并进入 `motor_test unloaded`。`zero`只清零，不主动定位，也不持久化。

**夹紧 / 松开**：

- **夹紧**（`close`，实测脉宽 `SERVO_CLOSE_US`）：推杆**往后拉**，上下轮胎压头接触魔方；主臂角约 3.84°、每侧轮胎压缩约 0.32mm 都只是名义模型值。当前名义夹紧位置在曲柄**折叠死点前 25°**，不是伸直死点，也不是必须拉到折叠成一线。实际夹紧力和保持能力须测量。
- **松开**（`open`，实测脉宽 `SERVO_OPEN_US`）：推杆**往前推**，名义行程约 12.92mm；曲柄经远离推杆的一侧张开约 **110°**。25° 和约 110° 是历史 v4 模型的 CAD 几何角度，不能换算为已测端点或直接脉宽跳转。具体装配和更新见 [v4 说明](https://github.com/gonewx/quadcuber/blob/e9d56112fa59c3301faa3b19b167e14e95b1e212/docs/lego/v4/README.md)。
- v4 舵机固定在平台上，不随机械头转动；不要套用旧中马达结构的舵机缠线角度限制。仍要手动确认实际线束没有进入任何运动包络。

**停下来**：

- 动作进行中按 **Ctrl+C**：程序停止马达输出，舵机停止 PWM，撤销标定会话，回到 `arm>` 提示符。
- `servo off`、`off`、`servo_cal end`：都停止马达输出和舵机 PWM，并撤销舵机标定及空载马达测试两种会话。**停 PWM 不等于切断舵机 5V，也不保证舵机卸力或夹指松开。**
- 退出、异常和 Ctrl+C 同样停止输出并清除两种会话；重启或重新创建控制对象也不会恢复。重新开始时必须重新声明。
- 程序没反应，或者马达／舵机自己转、发烫：**立即断开动力电源（包括舵机 5V）**，不要仅依赖串口停止命令。

**每次闭环动作打印一行 `RESULT {...}`**，常看这几个字段：

| 字段 | 含义 | 正常范围 |
| --- | --- | --- |
| `ok` | 是否成功到位 | `true` |
| `state` | `done` 成功；失败时是下面三种之一 | `done` |
| `t_settle` | 从开始到稳定在目标 ±`tol`（默认 2°）以内的时间（秒） | 越短越好，记下来 |
| `err` | 到位时的误差（度，机械头） | ≤ 2 |
| `err_rest` | 马达刹车、静止 150ms 后的误差 | ≤ 2；比 `err` 大很多说明被反推回去了 |
| `overshoot` | 冲过头多少度 | 小于 2~3 |
| `max_dt_us` | 控制循环最大间隔（微秒） | 1000 左右；经常几千说明 MicroPython 跟不上 |

失败时 `state` 是：

- `runaway`：越转越远，**几乎都是方向配错了**，回第 1 步；
- `stall`：马达用满力却转不动，可能是卡住，或者 `amax` 设得太大；
- `timeout`：到了附近但停不准，一般是摩擦大、`kp` 小。

失败后程序会自动给马达断电。

### 第 0 步：上电前检查（不放魔方）

1. 确认电源已在接负载前单独测量：9V 电源实测**不超过 10.8V**（之前实测约 7.9V），降压模块空载调至 **5.0V**。然后断开 9V 和 USB，核对完整接线，特别是 P04 直接回电源负极、舵机电源直连降压输出。
2. 检查机械头、推杆、十字块和线束的转动空间。只有传动已可靠脱开或能无阻力转动时才做断电手动检查；不要抓夹指强行回驱EV3减速器。带传动的转动检查采用下述已核实条件下的空载马达模式。
3. 不放魔方，给夹爪留出自由活动空间；首次舵机定位前先按第 3 步脱开连杆。先只插 USB，启动 `arm_test.main()`；出现 `arm>` 后输入 `off`，再接 9V。程序初始化时马达为滑行状态、舵机 PWM 关闭，不主动发送开合脉冲；**这只是软件不发命令，不能保证上电硬件不抖动**，仍需观察有无异常动作。
4. `enc`读取当前值；在传动可自由转动的条件下，或完成下一项授权后按第1步做短时空载驱动，再 `enc` 比较计数。不以强扳机械头制造计数变化；没有变化就按第3节查编码器。
5. **确认无魔方、机械头和联动机构全程自由、供电与接线已核验后**，输入 **`motor_test unloaded`**。它只进入空载测试模式，立即停止马达／舵机 PWM 并撤销舵机标定会话，不会自行转动。未校准时，该模式允许 `check`、`duty`、`speed`、`friction`、`rot`、`goto` 和 `bench ... free`；拒绝 `load`、`cube` 等承载标签，以及 `open`、`close`、`grip`、`cycle`。不能用它做带载测试。

每次 `off`、`servo off`、`servo_cal end`、Ctrl+C、异常、退出或重启后，空载模式都已撤销，继续动作前须重新检查并输入 `motor_test unloaded`。进入 `servo_cal` 也会停马达并撤销空载模式；舵机手动标定会话不会放行马达。

### 第 1 步：确认方向（不放魔方，夹爪留出活动空间）

先按第 0 步确认并进入 `motor_test unloaded`；下列任何配置修改、异常停止或重启后，都需重新进入该模式。

1. **`check 0.3`**：马达用 30% 占空比转 150ms。
   - 显示“几乎没有读数”：马达没转（查 9V、nSLEEP、AIN1/AIN2），或者编码器没信号（查分压电阻、黄/蓝线通断、4 脚 5V）。
   - 显示“方向相反”：马达和编码器不一致。把 `config.py` 里的 `ENC_INVERT` 改成相反的值，上传并 Ctrl+D 重启；重新核查并进入 `motor_test unloaded` 后再 `check`，直到显示“方向正确”。
2. **`duty 0.3 500`**：马达用 30% 占空比转 0.5 秒（机械头大约转 30~50°），**站在舵机那一头看机械头**：
   - 顺时针，而且打印的“转了 xx 度”是正数：方向完全正确，进行第 2 步。
   - 逆时针：把 `MOTOR_INVERT` 和 `ENC_INVERT` **两个都**改成相反的值（只改一个会变成“方向相反”），上传并 Ctrl+D 重启，重新检查、进入 `motor_test unloaded` 后回到 `check`。
3. **方向没确认之前，不要运行 `rot`、`goto`、`bench`、`cycle`**。程序会检测到 `runaway` 并断电，但马达会先猛转一下。

### 第 2 步：确认齿轮比

继续保持无魔方、全行程自由。`cal` 是手动计数，不主动转马达；如果此前 `off` 或重启，后续动力测试须重新进入 `motor_test unloaded`。

1. **`cal`**：程序先松开马达。在转盘上做个记号，用手把**机械头**转正好 1 圈，按回车。
2. 应显示约 **1800** 计数（720 × 2.5）。正负号无所谓（取决于你往哪边转）。
3. 程序会给出 `COUNTS_PER_MOTOR_REV` 的建议值。离 720 不超过 2% 就不用改（空载时测过 707，决定保留 720）；差很多先检查齿轮是不是打滑、跳齿。

### 第 3 步：标定舵机（先不放魔方）

**首次定位必须脱开曲柄与连杆，并确认曲柄本身能自由转动。** 舵机接收绝对脉宽，实际轴位未知时，首次定位可能大幅跳转；声明的脉宽区间不能证明实际轴位或机械行程安全。这里“脱开”指机械连接，三根电线可保持接好，装拆一律先切断动力电源和 USB。

当前配置已记录开合脉宽 `SERVO_OPEN_US = 1700`、`SERVO_CLOSE_US = 1450`，尚无已确认的安全工作区间：`SERVO_MIN_US = None`、`SERVO_MAX_US = None`；这两个脉宽不能直接视为适用于其他臂或装配的安全端点；标定身份 `SERVO_CALIBRATION_PROFILE` 和 `SERVO_CALIBRATION_ARM` 也均为 `None`，且 `SERVO_CALIBRATED = False`。时序默认 `SERVO_MOVE_MS = None`、`SERVO_TIMING_CONFIRMED = False`。端点与时序分两阶段确认；下面的手动会话不会自动扫角、自动测端点或自动写回配置。

#### A. 断电检查固定点

关闭 9V（确认舵机 5V 也已断开）、拔掉 USB，脱开曲柄与连杆，不放魔方。检查松脱处的销、梁孔、舵机安装耳和半轴套，损坏或明显松旷的零件先更换。

- **垫梁 → 平台**：按历史 v4 第 9、10 步使用 7 孔垫梁；从平台后端数，黑销在第 1、5、6 孔，第 2、4 孔下方被 55615 占用，不补插贯穿销
- **舵机 → 垫梁**：安装耳的蓝色长销插在第 3、7 孔；耳朵贴合，销插到底
- **平台 → 底座与竖墙**：核对前端竖墙、后端 55615、竖墙侧梁及舵机侧斜撑；轻推舵机本体观察安装耳、垫梁和整个平台，任何松动都先处理
- **连杆轴向固定**：按历史 v4 装齐曲柄端、十字块端的轴和半轴套；挡住退出的同时，连杆圆孔仍能自由转动。舵机连杆是 7 孔粗梁的第 1、7 孔，不能沿用旧孔位

安装图见 [v4 搭建说明书](lego/v4/index.html)，历史加固见 [v4 设计说明](https://github.com/gonewx/quadcuber/blob/e9d56112fa59c3301faa3b19b167e14e95b1e212/docs/lego/v4/README.md)。

#### B. 脱开连杆，声明会话后空载定位

1. 保持连杆脱开，确认曲柄全程不会碰到平台或其他部件。Pico 接 USB，启动并输入 `off`，再开动力电源；仍需防范上电抖动。
2. 人工选择本次检查允许的脉宽区间和基准值，输入 **`servo_cal <min_us> <max_us> <start_us> detached`**。三个数都必须是整数，满足 `500 <= min_us < max_us <= 2500` 且 `min_us <= start_us <= max_us`。**500～2500µs 只是驱动允许的包络，不是这套机构的安全行程，不能直接照抄为机械安全区间。** `detached` 声明连杆已脱开、曲柄可自由转动；程序无法替你检查实物。
3. `servo_cal` **只授权本次会话**：立即停止马达和舵机 PWM，撤销 `motor_test` 模式，不会定位。接下来必须先输入 **`servo <start_us>`**（用刚声明的同一个整数）才会实际发脉冲。不要把它当作微小相对位移；等舵机停稳后记录这次基准脉宽和输出轴姿态，它不代表夹紧端点。
4. 做好输出轴位置标记，执行 `servo off`，断开动力电源和 USB。停 PWM 不等于切断 5V，也不保证松开；必须确认动力电源确实断开再装配。

#### C. 断电装接，核实轴位后重新声明

1. 手动将夹爪和推杆放在行程中间，远离端部、挡轴及曲柄折叠死点；不要靠强扭舵机轴来移动机构。
2. 调整曲柄在输出轴上的安装方向，使连杆自然对孔，装好连接轴和半轴套。不能对孔时先检查朝向和孔位，不硬拉或靠通电拉到位。
3. 核实舵机轴标记未变、记录的基准脉宽仍对应当前装接姿态，且计划的小步行程无障碍。只有这些条件成立，才先只接 USB、启动程序；保持动力关闭，重新选臂（L 用 `arm L`，R 用 `arm R`），输入 `arm` 核对目标和引脚后，再接通已检查的动力并声明 **`servo_cal <min_us> <max_us> <start_us> aligned`**；`start_us` 用刚才已建立且核实过的基准。`aligned` 不是绕过首次脱杆定位的选项。
4. 声明本身仍不移动；输入相同的 **`servo <start_us>`** 后观察底座和连杆。轴标记不确定、装配时轴转过或无法核实对应关系，就重新脱杆执行 B，不尝试带机构找零。

#### D. 手动寻找端点与安全工作区间

首次基准脉冲之后，每条 **`servo <us>`** 可直接指定本次声明区间内的任意整数脉宽，**不再限制相邻命令的脉宽差值**；超出区间仍会被拒绝。这是绝对目标值，不是相对增量，也不控制舵机运动速度。只有确认两个位置之间的整个行程都无障碍，才增大跨度；未知区域和端点附近仍建议每次 10～20µs、停稳观察后再继续。不要直接套用旧的 1200/1800，也不要自动扫角。需要重新声明时，会先停 PWM；必须再次核实 `detached` 或 `aligned` 的前提及基准，首条仍须为声明的 `start_us`。

**出现持续嗡响、机构顶住、底座抬起或销退出，立即切断动力电源（含舵机 5V）；能及时操作串口时也可先发 `servo off`。** 不用手扶住正在受力的机构继续试。

1. 不放魔方，小步确认脉宽哪个方向让推杆往后拉、哪个方向往前推。夹紧是**往后拉**；名义夹紧在**曲柄折叠死点前 25°**，曲柄和舵机连杆不是伸直到死点。不要以碰到导向或折叠死点为目标，不尝试越过死点。
2. 从已确认位置小步寻找张开端：夹指张开足够，推杆、十字块、连杆及挡轴均不顶住。约 110° 只是 CAD 的名义曲柄张开行程，不能据此推算安全脉宽。
3. 无负载行程确认后，夹紧端还需用有支承的魔方轻载确认：先断电放置魔方、检查轮胎与轴套，再按 C 核实轴位并重新声明 `aligned` 会话。只用小步让上下轮胎均接触并有适当预压，观察轴套是否滑移、底座是否抬起。记录开／合端点及覆盖两端的**实测安全工作区间**；不要求任何连杆到达死点，不以加大行程补偿松旷。
4. **只有上述实物确认完成后**，人工写入 `SERVO_OPEN_US`、`SERVO_CLOSE_US`、`SERVO_MIN_US`、`SERVO_MAX_US`。四个值须为严格整数，端点互异且在实测工作区间内；工作区间仍须处于 500～2500µs 驱动包络内，不能把包络本身当成实测区间。当前机械身份是 `MACHINE_PROFILE` 为 `"v4"`，`ARM_ID` 为所选臂 `"R"` 或 `"L"`；同时填写 `SERVO_CALIBRATION_PROFILE` 为 `"v4"`、`SERVO_CALIBRATION_ARM` 为该臂身份，最后才设置 `SERVO_CALIBRATED = True`。固件检查全部字段与身份匹配。换臂、重装或调整机构后不能沿用未经重新确认的标定。
5. **先进入单次开合测时阶段**：端点、安全区间和身份已确认后，人工为 `SERVO_MOVE_MS` 设置一个明确、保守的临时等待时长，必须是 **1～5000ms 的整数**；保持 `SERVO_TIMING_CONFIRMED = False`。这不是本机实测时长，不能简单沿用旧的 120ms。结束会话、关闭动力电源，上传 `config.py`，在 REPL 按 **Ctrl+D 软重启**后启动程序后重新选臂（L 用 `arm L`，R 用 `arm R`），输入 `arm` 核对目标、引脚和配置。确认整个行程无障碍后再通电，**每次只单独执行一条 `open` 或 `close`，观察完全停稳才发下一条**；出现提示符不代表实物已经到位。用手机慢动作录像测量完整开、合行程的实际停稳时间。
6. 测时阶段的 `grip`、`cycle`、普通 `rot` / `goto` / `bench` 等旋转路径仍被时序门禁锁住；不能靠调短等待时间或提前设置标志解锁。`motor_test unloaded` 仍是经过明确声明的空载例外，不能用来做承载或联合动作。
7. **实测时序后再解锁连续动作**：取开／合中较慢的实测停稳时间并加足余量（例如至少再留约 20ms，按实际抖动调整），写入 `SERVO_MOVE_MS`（仍须为 1～5000ms 整数），设置 `SERVO_TIMING_CONFIRMED = True`。重新关闭动力电源、上传并 Ctrl+D 重载，重新选臂（L 用 `arm L`，R 用 `arm R`），输入 `arm` 核对目标、引脚和配置后才接通动力，再执行 `grip 5`，通过后才进入后续旋转与联合测试。机构、负载条件或供电变化后要重新确认时序，不能沿用未经核实的 True 标志。

**会话边界**：`servo off`、`off`、`servo_cal end`、退出、异常或 Ctrl+C 会停止马达输出和舵机 PWM，并撤销两种会话；重启、重新创建控制对象也不会恢复会话。手动会话中 `open`、`close`、`grip`、`cycle` 及所有马达驱动命令都被拒绝。要继续标定必须重新声明，并重新满足机械检查前提。

### 第 4 步：测起转力和速度（不放魔方）

先完成第 3 步的端点与时序两阶段确认。装上机械头以后，转动部分的惯量和摩擦都和空载不一样，这两个要重测。

1. **`friction`**：占空比从 0 慢慢加大，两个方向各测一次，记下建议的 `kfs`。
2. **`speed`**：全速转 0.4 秒，机械头会**连续转大约半圈**，先确认没有东西挡着。记下建议的 `v_full`、`tau`。
   - `speed` 算建议值时要扣掉当前的 `kfs`，所以跑 `speed` 之前先用 `set kfs <第 1 步的建议值>` 把它改过来。
3. 把三个值填进 `config.py` 所选臂分组内的 `GAINS`，上传，动力保持关闭、重新启动后先重新选臂（L用 `arm L`，R用 `arm R`），`arm` 核对后按第4.5节B重新建立实际机械零位；不强行手转减速器，不沿用重启前的软件零位。

### 第 5 步：空转 90° / 180°（不放魔方）

1. **`open`**，然后 **`rot 1`**：机械头应**顺时针**转 90°，打印 `RESULT`，`ok` 为 `true`。再 **`rot -1`** 转回来。
2. **`bench 1 20 free`**：来回转 20 次 90°。最后一行是统计（成功次数、平均/最长到位耗时、平均/最大误差）。
3. **`bench 2 10 free`**：来回转 10 次 180°。
4. 通过标准：全部成功；最大误差 ≤ 2°；`max_dt_us` 在 1000 左右。不通过就看后面的“调参提示”。

### 第 6 步：测回差（不放魔方）

编码器装在马达上，齿轮和转盘之间的间隙它读不到，**只能看机械头本身**。

1. 在机械头上贴一段纸条当指针，后面放一张画了刻度线的卡片（指针长 100mm 时，1° ≈ 1.7mm）。
2. `rot 1` 到位后（马达处于刹车状态），先 `enc` 记下计数，用手轻轻来回扳机械头（不要用力），用手机拍指针，量来回的空转角度。
3. 再 `enc`：计数应不变。变了说明是马达被扳动了，不是齿轮间隙。
4. 空转超过 ±1° 要告诉我，这会直接叠加到魔方面的误差上。

### 第 7 步：夹住魔方（先不转）

以下是历史独立单臂台架步骤，不适用于原上位托盘上的L/R竖直闭合；当前L/R定位与装料准备先执行第4.5节，未到达其阶段2以前不进行双臂接管。

1. `open`，把魔方放进两片夹指之间，`close`。
2. 停止动作并切断动力、由独立支承托稳后，观察压点是否跨缝，以及上下压点同向还是反向偏；记录现象即可，不要求反复拍照，不在带电受力时用手扶正机构。
3. 扭一下被夹住那一层：夹指应带着这一层，不打滑；推杆不应被顶回去。
4. `open`：夹指松开时不应把魔方带歪。

### 第 8 步：夹着魔方拧面

需要用手或一个临时夹具固定魔方的另外两层，只让被夹的那一层转动。

1. **`bench 1 20 load`**、**`bench 2 10 load`**：夹着魔方拧 90° / 180°。
2. **`cycle 20`**：夹紧 → 拧 90°（记为 load）→ 松开 → 空转回来（记为 free），重复 20 次，最接近实际工作的情况。**录像**，看：
   - 魔方有没有打滑、夹爪松开时有没有把魔方带歪；
   - **魔方面实际转到的角度**：拧完后这一层和另外两层对不对齐。判断靠魔方，不靠编码器（中间还有回差和夹指间隙）。
3. 频繁 `stall`：说明拧魔方需要的力超过了设置，先减小 `amax`，再告诉我。

### 第 9 步：汇总

在 PC 上跑第 6 节的命令，把 `arm.log` 变成 `timing.json`。

### 调参提示

每次只改一个参数，改完跑 `bench 1 20 free` 对比。

- 太慢：逐步加大 `set vmax 300`、`set amax 3000`（当前初始值 240、2400 来自空载参数按齿轮比换算，装机后须重测）。
- 冲过头、来回抖：减小 `kp` 或加大 `kd`；也可能是 `v_full` 填小了（前馈过强）。
- 到不了位（`timeout`）：加大 `kp`，或加一点积分 `set ki 0.5`。
- 频繁报 `stall`：加速度超过了马达能力，减小 `amax`。
- 到位后还想多保持一会儿再刹车：`set hold 100`（默认 50ms）。
- `trace` 会输出上一次动作的轨迹（时间、参考位置、实际位置、占空比），复制到表格软件里画图，调参会直观很多。

## 6. 把结果交给规划器

```bash
python -m quadcuber armlog arm.log -o timing.json
python -m quadcuber bench --timing timing.json --compare
```

`armlog` 会打印每类动作的耗时和误差统计，把平均耗时写进 `timing.json`；`bench` 用实测耗时重新估算整机速度。
