# 单臂原型：接线与测试步骤

目标：用 **1 个机械手**（夹紧 + 旋转）回答三个问题，决定整个方案是否可行：

1. 转 90° 要多久？（直接决定总时间）
2. 到位精度多少？（误差大了，下一次拧面会卡住）
3. 夹持是否可靠？（拧面时魔方不打滑、不掉）

> **图解版接线指南**：[docs/wiring/index.html](wiring/index.html)（已发布：https://claude.ai/artifact/9V1v8omZyuEr52coL2C6QV ），有总览图、可按类别筛选的完整接线图、分步接线清单、Pico 引脚图和上电前检查表。内容与本文第 2、3 节一致。

这份文档讲**电路和测试步骤**。机械手（乐高结构）怎么搭，见 [arm_concept.md](arm_concept.md)：其中有结构思路、关键尺寸和单臂测试时固定魔方的办法。

> ⚠️ **固件已在用户 Pico 上进入单臂命令界面，但整机闭环尚未实物验证。** 控制逻辑在 PC 上用模拟环境测过（马达模型 + PIO 解释器，见 `tests/pico_sim.py`），能证明逻辑和指令编码没有明显错误，但证明不了实物一定能用。先按第 3 节接好编码器分压电阻并完成手动转轴验收，再运行会使马达转动的 `check`。

> **编码器接口（2026-09-27 最终方案）：每路两个电阻做分压，不用电平转换模块。** 原 BSS138 接法已撤回，原因和测量依据见 [接口复核报告](ev3-interface-verification.md)。

## 1. 需要的东西

| 物品 | 说明 |
| --- | --- |
| 树莓派 Pico | 刷 MicroPython（官网 UF2，按住 BOOTSEL 插 USB，把 UF2 拖进去） |
| DRV8833 模块 ×1 | 单臂只用 A 路 |
| EV3 大马达或中马达 ×1 | 需要能接出 6 根线：剪一根 EV3 线，或者用 EV3 接口转接板 |
| Geekservo ×1 | 夹爪开合 |
| 电阻 | 10kΩ ×2（串联）+ 20kΩ ×2（下拉）；没有 20kΩ 可用 22kΩ 或两个 10kΩ 串联，见第 3 节 |
| 9V 电源 | 2 节 18650 + LM2577 升压到 9V，或 PD 充电宝 + 9V 诱骗线 |
| 5V 降压模块（≥3A） | 给舵机单独供电，以及给编码器供电 |

## 2. 引脚分配

单臂原型用 R 臂的引脚。整机 4 个臂的分配已经一起排好，**PWM slice 不冲突**（RP2040 上 GPIO 号相差 16 的两个引脚共用同一路 PWM，不能随便挑）：

| 用途 | R 臂 | L 臂 | F 臂 | B 臂 |
| --- | --- | --- | --- | --- |
| 马达 IN1 / IN2 | GP2 / GP3 | GP6 / GP7 | GP10 / GP11 | GP14 / GP15 |
| 编码器 A / B | GP4 / GP5 | GP12 / GP13 | GP16 / GP17 | GP18 / GP19 |
| 舵机 | GP8 | GP9 | GP20 | GP21 |
| PIO 状态机 | 0, 1 | 2, 3 | 4, 5 | 6, 7 |

- UART 连 Zero W：GP0（TX）→ Zero 的 GPIO15（RX），GP1（RX）← Zero 的 GPIO14（TX）。
- 剩余引脚：GP22、GP26、GP27、GP28，可以留给限位开关或 DRV8833 的 nFAULT。
- 编码器用 4 倍频，每个编码器占 2 个 PIO 状态机，4 个臂正好用完 8 个。如果以后 PIO 不够用，可以改成 2 倍频（每个编码器 1 个状态机，分辨率减半）。

## 3. 接线

### EV3 线（6 芯）

| EV3 脚 | 常见线色 | 功能 | 接到 |
| --- | --- | --- | --- |
| 1 | 白 | 马达 M1 | DRV8833 AOUT1 |
| 2 | 黑 | 马达 M2 | DRV8833 AOUT2 |
| 3 | 红 | GND | 公共地 |
| 4 | 绿 | 编码器电源 | 5V（降压模块） |
| 5 | 黄 | 编码器 A 相 | 10kΩ → GP4（GP4 再经 20kΩ 接地） |
| 6 | 蓝 | 编码器 B 相 | 10kΩ → GP5（GP5 再经 20kΩ 接地） |

> ⚠️ 线色是常见的配色，**不同的线可能不一样，以万用表通断为准**。马达的两根线（1、2 脚）之间电阻大约几欧到十几欧，可以借此确认。

### 编码器分压（重要）

**RP2040 的引脚不耐 5V**，编码器信号直接接 Pico 会损坏芯片。

LEGO 官方电路：EV3 马达里两路编码器都是施密特缓冲器，**推挽输出 0V/5V**，各经一个串联电阻到插头：6 脚（蓝）3.3kΩ，5 脚（黄）的电阻兼作马达型号识别（大马达 3.3kΩ、中马达 6.8kΩ）。所以每路只要两个电阻分压：

```
EV3 黄 ──[10kΩ]──●── GP4        EV3 蓝 ──[10kΩ]──●── GP5
                 │                                 │
              [20kΩ]                            [20kΩ]
                 │                                 │
                GND                               GND
```

- ● 是面包板上的同一排：10kΩ 的一脚、到 GP 引脚的跳线、20kΩ 的一脚插在一起；20kΩ 的另一脚接地轨。
- 算上马达内部电阻，高电平：大马达约 5 × 20 / 33.3 ≈ 3.0V，中马达黄线约 2.7V；低电平约 0V。Pico 要求高 ≥ 2.0V、低 ≤ 0.8V，裕量充足。
- 替代阻值（结果都在 2.7~3.0V）：20kΩ 换成 22kΩ 或两个 10kΩ 串联；或者 4.7kΩ 串联 + 10kΩ 下拉。
- 固件里 `ENC_PULLUP = False`，不能开 Pico 内部上拉（会抬高分压点）。
- **接 Pico 之前先验收**：编码器通电（绿 5V、红地），分压点先不接 Pico，用万用表量分压点对地的电压；手转输出轴，每次转一点停下来读，应在约 0V 和约 3V 之间变化，**任何时候都不能超过 3.3V**。两路都正常再接 GP4/GP5。

不要用 BSS138 或 TXS0108E 电平转换模块：马达内部的串联电阻和 BSS138 模块的上拉会分压，低电平只能到约 1.65V（实测 1.60~1.64V）；TXS0108E 要求信号源内阻很低，同样不适用。

### 马达驱动

| DRV8833 | 接到 |
| --- | --- |
| VM（有的标 VCC） | 9V；本版不另装电容，保留模块自带电容 |
| GND | 公共地 |
| AIN1 / AIN2 | GP2 / GP3 |
| AOUT1 / AOUT2 | EV3 线 1、2 脚 |
| nSLEEP（有的标 EEP / STBY） | **必须为高电平**，很多模块板上已经上拉；没有的话接 Pico 3V3 |

> ⚠️ **DRV8833 的马达电压最高 10.8V，不能接 12V。** PWP/RTY 封装每桥为 1.5A RMS、2A 峰值，PW 封装为 0.5A RMS、2A 峰值；实际板卡受散热和限流设置影响。大马达 9V 堵转实测约 1.8A，不能当持续工作点；软件保护不能代替硬件限流。当前驱动板的电流裕量尚未确认。

### 舵机

- 信号线 → GP8；电源 → **单独的 5V 降压模块**（不要从 Pico 取电，舵机启动电流会让 Pico 复位）；地线 → 公共地。

### 供电和地

- 所有模块**共地**：Pico GND、DRV8833 GND、5V 降压模块 GND、9V 电源负极、EV3 线 3 脚。
- 调试时 Pico 用 USB 供电即可。以后脱离电脑时，从 5V 经**肖特基二极管**接 VSYS（防止和 USB 供电互相倒灌）。

### 洞洞板固定接线（推荐）

洞洞板上只焊插拔端子底座、排母和配线：DRV8833 插在排母上，电源和马达裸线接可拔端子、舵机母头接排针、控制公头线接排母，降压模块通过四角排针插入排母；Pico 与编码器分压电阻继续留在面包板上。大电流用专用铜导线和合适的端子连接，普通排线用于控制信号。洞洞板焊盘不能仅靠连锡承担主电流。

完整方案见 [洞洞板设计](perfboard.md) 和 [图解布局及端子表](wiring/index.html#perfboard)：包含 J1～J7 端子定义、32×24 孔阵的安装图、镜像焊接图、14 根逐孔焊线以及[面包板与洞洞板实际连接图](wiring/perfboard.html#bridge)、[舵机与马达完整连线图](wiring/perfboard.html#loads)。图示驱动按用户提供脚序：左上 VM、右上 NC，STBY 经控制接口接 Pico 3V3；本版不另装电容，降压模块不用螺钉或支柱。沿用现有 GPIO；单臂调试仍由 USB 给 Pico 供电。

## 4. 刷程序

在 PC 上安装 `mpremote`（`pip install mpremote`），Pico 刷好 MicroPython 后：

```bash
cd firmware/pico
mpremote cp config.py control.py encoder.py motor.py arm_test.py :
mpremote repl --capture arm.log      # 串口输出同时保存到 arm.log
```

在 REPL 里输入：

```python
import arm_test; arm_test.main()
```

用 Thonny 也可以：把 5 个文件上传到 Pico，运行 `arm_test.py`，最后把 Shell 窗口的输出全选复制到 `arm.log`。

## 5. 测试步骤

每一步的命令都在 `arm>` 提示符下输入，`help` 可以查看全部命令。

### 第一步：不装机械手，只接马达

1. **`check`**：马达正转 150ms，检查编码器有没有读数、方向对不对。
   - "几乎没有读数"：马达没转（查 9V、nSLEEP、AIN1/AIN2），或者编码器没信号（查分压电阻、黄/蓝线通断、4 脚 5V）。
   - "方向相反"：把 `config.py` 里的 `ENC_INVERT` 改成 `True`，重新上传后再 `check`。
   - **方向不对时不要运行 `rot` 等闭环命令**（程序会检测到失控并断电，但马达会先猛转一下）。
2. **`cal`**：用手把马达输出轴转正好 1 圈，看计数是不是 720（4 倍频）。不是的话，把实测值填进 `COUNTS_PER_MOTOR_REV`。
3. **`friction`**：测起转占空比，把建议的 `kfs` 记下来。
4. **`speed`**：全速转 0.4 秒，测空载速度和时间常数，把建议的 `v_full`、`tau` 记下来。
5. 把上面的值填进 `config.py` 的 `GAINS`，重新上传。
6. **`rot 1`**、**`rot -1`**：转 90° 看看。成功会打印 `RESULT {...}`，其中 `t_settle` 是到位耗时，`err` 是到位误差。
7. **`bench 1 20`**：来回转 20 次，看统计结果。

### 第二步：装上机械手（先不夹魔方）

1. 如果机械手和马达之间有齿轮，改 `GEAR_RATIO`，再做一次 `cal`（这次转机械手 1 圈）。
2. **`servo 1500`** 等命令：试不同的脉宽，找到叉子"后退"（松开）和"前进"（夹紧）的位置，填进 `SERVO_OPEN_US`、`SERVO_CLOSE_US`，并确认退出行程 ≥ 13mm（见 [arm_concept.md](arm_concept.md)）。
3. **`grip 5`**：开合 5 次，**用手机慢动作录像**，看舵机从发出指令到到位要多久，填进 `SERVO_MOVE_MS`。
4. **`bench 1 20 free`**、**`bench 2 10 free`**：空转 90° / 180°。

### 第三步：夹魔方拧面

需要一个临时夹具（或者用手）固定魔方的另外两层，只让被夹的那一层转动。

1. **`bench 1 20 load`**、**`bench 2 10 load`**：夹着魔方拧 90° / 180°。
2. **`cycle 20`**：夹紧 → 拧 90° → 松开 → 转回，重复 20 次，最接近实际工作的情况。**观察魔方有没有打滑、夹爪松开时有没有把魔方带歪。**

### 调参提示

- 太慢：逐步加大 `set vmax 800`、`set amax 10000`，每次改完跑 `bench` 看结果。
- 冲过头、来回抖：减小 `kp` 或加大 `kd`；也可能是 `v_full` 填小了（前馈过强）。
- 到不了位（`timeout`）：加大 `kp`，或加一点积分 `set ki 0.5`。
- 频繁报 `stall`：加速度设得超过了马达能力，减小 `amax`。
- `trace` 命令会输出上一次动作的轨迹（时间、参考位置、实际位置、占空比），复制到表格软件里画图，调参会直观很多。
- 每条 `RESULT` 里的 `max_dt_us` 是控制循环的最大间隔。正常应在 1000 左右；如果经常到几千，说明 MicroPython 跟不上（垃圾回收等），请告诉我。

## 6. 把结果交给规划器

```bash
python -m quadcuber armlog arm.log -o timing.json
python -m quadcuber bench --timing timing.json --compare
```

`armlog` 会打印每类动作的耗时和误差统计，把平均耗时写进 `timing.json`；`bench` 用实测耗时重新估算整机速度。
