# A1 剩余验证：设计规则与独立子电路校核

2026-10-12。此次完成原厂数据表核读、有限容差计算及EN无开关子电路的实际ngspice运行；没有重复四项WEBENCH默认测试、修改PCB/BOM或改变芯片模型。**发现两项需先处理的设计依据问题：BOOT串49.9 Ω缺乏当前引用参考电路的支持；反馈全容差静态上限超过项目5.25 V。** 制造仍NOT RELEASED。

## 1. BOOT 49.9 Ω：参考位置与当前A1不一致

[TI TPS54302数据表Rev C](https://www.ti.com/lit/ds/symlink/tps54302.pdf)第14页图7-1已下载、提取文字并渲染实际核读：BOOT–SW之间为直接连接的100 nF；图中49.9 Ω位于Vout与反馈上臂/前馈网络之间。第15页7.2.3.3明确说明该49.9 Ω用于断开反馈环路、做稳定性测试。它**不是该参考设计的BOOT阻尼电阻**。

当前A1定义R20/R30=49.9 Ω，连接BOOT→BOOT_CAP，C22/C32从BOOT_CAP到SW；这是实际源连接，不是报告命名问题。本次脚本对两路数值及A路连接做断言。没有找到独立EMI/开关边沿实验或TI器件专用依据来支持将49.9 Ω放在这里；不能确定历史设计动机，但不能再引用图7-1作为该BOOT串阻的依据。

数据表6.3.10要求100 nF，BOOT-SW>2.1 V为典型驱动条件，推荐范围上限5.5 V。49.9 Ω×100 nF=4.99 µs，而400 kHz周期2.5 µs。此RC比较只是风险筛查：真实充电回路和高侧栅极驱动非简单RC，不能由此断言一定失效。内部栅极电荷、驱动峰值和实际BOOT电流波形不足，不能可靠计算其峰值压降、平均损耗、启动时序或热裕量。对独立理想RC跑更多波形也补不了这些缺失。

**建议提出设计修订评审**：检查R20/R30是否应改为0 Ω连接以恢复官方直接bootstrap电容拓扑；原焊盘可能可保留，但须核对实际回路/布局和装配BOM，不能只改仿真。若仍需BOOT阻尼，数值必须由器件专用证据和边沿/BOOT电压/损耗测量决定，不能默认保留49.9 Ω。可选反馈注入电阻是另一功能，是否增加需单独评审。**本次未实施任何这些改动**，也未以短接串阻“修复”既有失败记录。

## 2. EN 511 kΩ/105 kΩ：有官方参考，完成独立核算

Rev C图7-1使用相同分压；6.3.5的内部上拉Ip=0.7 µA，启用后额外Ih=1.55 µA；典型上升阈值1.23 V、下降1.16 V。由节点KCL得到：

`Vstart = 1.23 × (1+511/105) − 0.7µA×511kΩ = 6.8583 V`

`Vstop = 1.16 × (1+511/105) − 2.25µA×511kΩ = 5.6556 V`

典型迟滞1.2027 V，超过该节建议的0.5 V。仅计两只1%电阻角点，启动6.7433–6.9757 V，停止5.5553–5.7581 V。不能把这些区间当完整PVT保证：Ip/Ih只给典型值，阈值也不是对称完整min/max表。

保守忽略正向上拉、使用上升阈值最大1.28 V和电阻最坏比值，启动电压上界条件值7.6352 V，低于芯片输入最小测试值8.82 V；它以EN无额外负向漏电为条件，不替代完整器件PVT资格。工作在8.82–9.18 V时，按典型电流和电阻角点EN约1.67–1.79 V，低于推荐5.5 V。仅据此无须改这组分压。

若输入按原测试0→9 V、1 ms线性上升，典型EN越阈约0.762 ms；再加典型5 ms软启动，粗略预计约5.76 ms。两者均非最大值保证，且BOOT和实际负载仍影响动态。浮空EN的WEBENCH启动不能替代该时序。

已运行[en-independent.cir](en-independent.cir)：1001个0–10 V直流点，分别核算关闭/开启两条电阻+上拉电流支路，与独立KCL最大差4.55 nV，见[结果](en-independent-result.json)、[日志](en-independent.log)、[数据](en-independent.txt)。这是外围静态验证，不是完整TPS宏模型或EN比较器动态恢复成功。

[TI EVM指南Rev B](https://www.ti.com/lit/pdf/slvuap9)使用不同的历史典型阈值，表述启动6.74 V/停止5.83 V；本次不将其数值与Rev C混用。现有原始LIB也不能自动当作Rev C全容差模型。

## 3. 反馈容差：典型输出合适，但严格5.25 V上限尚无保证

Rev C反馈基准min/typ/max=0.581/0.596/0.611 V；现有R21/R31=100 kΩ、R22/R32=13.3 kΩ，均为Yageo F级1%。独立静态角点得到：

- 典型：5.07720 V；解释了PDF设计表5.077 V。此前0.6 V计算的5.1113 V仅为近似基准示例，不是数据表典型值。
- 低端：4.86292 V；高端：**5.29779 V**，比5.25 V高47.79 mV。

此计算未计输入偏置电流、线/负载调节和动态；不证明实物一定过压，但已经足以说明当前元件不能仅凭典型波形保证严格上限。建议评审反馈电阻精度/比值和静态/动态裕量分配，之后才做定向瞬态验证；不自行放宽验收或更改电阻。需要用实际选定料号重新检查温漂/容差，不能只在模型里减小误差。

已有0.4/0.8/1.2系数仅为敏感性假设。按数据表7.2.3.5.2粗估 `f0≈5.1/(Vout·Cout)` 且未计Cff时要求低于40 kHz，在典型5.0772 V下需**总有效Cout>约25.11 µF**。0.4系数的17.6 µF对应约57.07 kHz，不满足该初步设计规则；35.2/44/52.8 µF对应28.54/22.83/19.02 kHz。不能据粗估声称必然振荡，也不能把0.4角点称已证明合理。75 pF的效果及相位裕度仍须在确认有效C之后验证；不按估算自动改Cff。

## 5. WEBENCH拓扑与导出能力：不再要求用户反复找添加按钮

已可见UI提供CUSTOMIZE、元件替换/自定义参数及EXPORT，但没有验证当前TPS54302登录后导出菜单或可运行网表。用户四份PDF只证明报告导出。

[TI官方工具页](https://www.ti.com/tool/WEBENCH-CIRCUIT-DESIGNER)当前声明支持CAD导出，**并不保证当前器件提供PSpice仿真工程或通用SPICE网表**。[TI E2E官方答复（2021）](https://e2e.ti.com/support/tools/simulation-hardware-system-design-tools-group/sim-hw-system-design/f/simulation-hardware-system-design-tools-forum/906962/webench-tools-about-webench-tools-want-to-add-and-remove-components)说明该WEBENCH界面不支持增删元件，建议导出后修改；此次全文访问403，搜索返回该答复内容，属历史支持说明，不冒称已亲测2026菜单。

据此不假设可在线增加BOOT/EN，也不引用早期Schematic Editor宣传承诺当前功能。下一项界面核实应只做一次：用户已登录页面的EXPORT可用格式；若仅CAD/PDF，它不能解决动态求解问题；若提供仿真工程，取得实际内容并检查格式、模型许可及可用求解器。没有接管用户会话或发送登录凭据。

## 6. 有限的下一步与停止条件

1. **先设计依据评审**：BOOT49.9 Ω位置与反馈容差是当前优先问题。提出修订理由/影响后再变更真实设计；当前PCB不动。EN支路已完成有限静态校核，无需再盲扫其分压。
2. **取得准确电容特性并核实一次EXPORT能力**：父对话若能从官方入口取得曲线/导出，可继续接收，不需重复四份PDF或默认作业。缺少曲线时不将猜测ESR/C效值固化为实物参数。
3. **选择能表达实际拓扑的动态路径**：现成官方PSpice原工程可用于支持的求解器；WEBENCH导出只有确实包含可运行模型才算替代路径。没有该能力时，独立规则/EN验证仍有价值，但不伪装整机瞬态验收。
4. **Linux原振荡器仅保留一个有界研究入口**：既有18项A1失败、原参考约1.65 MHz异常、独立振荡器首比较器事件失败已有证据。若继续，目标只限原振荡器事件/迟滞/复位语义与可信参考轨迹的对照；先取得多个调制周期的内部/开关时序基准，再做一个明确语义修复候选。没有参考不替换成理想400 kHz时钟后宣称原模型通过，不再扫全板容差/求解参数。当前新发现的外围设计依据问题应先解决，继续全模型兼容试错优先级降低。
